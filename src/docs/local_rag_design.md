# 引得本地 RAG 设计

2026-11-25，设计基线为桌面版 `debfeb2`。交付目标是让用户在一个搜索框提问，先看到可阅读的史料，再看到能逐句点回出处的现代汉语解释。第一版面向本人的 Windows 桌面。以下接口、预算和上线门槛均为设计目标。

## 可行性与本机条件

检索、原文定位和本机推理都有可复用实现。主要风险在于模型会用真实引文支持错误的事件。Qwen2.5-14B 在陈平正反两题均完成推理，耗时约 82 和 73 秒，按完整标准通过 0/2。反例把离开项羽的原因套给了离开魏王。Qwen3.5-9B 在固定预算的反例中能拒绝错误说法，但用了约 175 秒，人物与事件解释仍不完整。同一模型再审自己提出的主张也出现过错误确认。[14B 原始实验结论](qwen25_reader_pilot_result.md) · [9B 反例复核](native_reasoning_budget_contrast.md) · [逐项主张复核](event_claim_trust_review.md)

仓库内已有 Qwen3-4B、Qwen3-8B（均为 Q4_K_M）、Qwen3.5-9B（Q5_K_M）及 Qwen2.5-14B-Instruct（Q4_K_M，三片）GGUF 权重。现有实验由 Python 管理 llama.cpp 子进程，已有 CPU 和 Vulkan 运行包。首轮选用已配置的 Qwen3-4B CPU 作为单段释读基线，质量和响应时间以新任务实测为准。模型随本地配置选择，桌面包与权重分开管理。[本地运行器](../search/local_evidence_reader.py) · [既有模型对照](controlled_reader_model_comparison.md)

## 搜索框到答案

1. **搜索一次。** 桌面沿用标点本统一检索入口及已有词面、语义和重排路径。关键词直接返回原文，问题返回同样可独立使用的结果卡。本地问答开关开启后，问题可继续生成。保留 Result Block 和 Kanripo 定位。首轮使用当前真实候选，避免更换检索策略后无法判断改进来自哪里。[统一检索入口](../search/punctuated_search.py) · [证据排序](../search/evidence_pipeline.py)
2. **建立本次证据清单。** 检索端持有短期、绑定桌面会话的结果快照。按前五条选足以说明事件的完整句、必要上下文及身份旁证。重叠片段按版本和原文区间去重。仅有身份开篇或同名材料时直接提示证据不足。模型只接收问题和本批编号材料，不能自行添加书目或调用工具。
3. **在本机释读。** 桌面后端持有进程，复用模型权重校验、随机端口、回环监听、临时密钥及退出清理。模型缺失、超出上下文预算或用户取消时，保留已经返回的史料。正文和完整引语优先，超长时减少材料数并记录省略范围。首轮每问最多一次生成；新查询使旧任务失效，迟到的结果不得覆盖新页面。[进程管理](../search/local_evidence_reader.py) · [桌面会话](../desktop/runtime.py)
4. **逐条核验后展示。** 首屏显示原文，生成完成后在同一页面增加“本地 AI 释读”。模型只写短主张及其证据编号，前端从已通过校验的主张组装解释，每句话旁边显示可点击的来源。校验失败、生成中断或请求超时时保留原文，并显示原因。

建议新增桌面会话内的生成操作，输入只含本次检索的快照编号。服务端从快照恢复问题、范围和出处；快照过期则要求重新检索。现有实验问答接口在生成分支构造 AnthropicProvider，同时会先让模型规划、再自行检索。桌面本地模式应走独立的本地 provider 入口，从普通搜索与旧实验生成入口都封住外部传输路径。模型进程只接受本机桌面后端请求，使用离线权重。GitHub Pages 继续承载静态阅读；本方案的计算、存储和日志都在用户电脑上。[现有接口](../api/main.py) · [既有问答流程](../search/history_qa.py)

## 引用契约与可信边界

| 数据 | 由谁产生 | 核验及用途 |
|---|---|---|
| 证据编号，如 E1 | 搜索后端 | 仅在当前快照有效，指向固定版本中一个可定位的证据单元 |
| 标点本文字 | 史料适配器 | 保存书卷、正文或注文、页号、修订号、来源哈希、原文块及字符范围；由原文库重建并逐字核对 |
| Kanripo 文字 | 原版适配器 | 保存书卷、版本、文件哈希、段落 ID 和原文位置。版本间有可靠映射才提供对读链接，并注明映射依据 |
| 主张与状态 | Qwen 草拟，后端检查 | 每条包含释读文字、所引编号及陈述来源。输出可为释读草稿、证据不足或记载有异。所有历史断言都经过同一校验，包括不确定性说明中的断言 |

原文按所引版本展示，简体阅读转换仅用于显示。正文、裴注、注中转引分别标明层次和来源。逐字核对证明引文真实；主张是否受到支持，还要核对人物、动作、对象、时地、否定和发言者。后端根据原始定位生成链接，拒绝其他查询的编号、越界坐标、哈希不符或截断引语。旧验证器的“每条论断有引用”契约可以复用，其 passage ID 和链接生成方式只适用于原有数据结构，标点本应沿用自己的版本坐标。[既有回答校验](../search/history_qa.py) · [上下文重建](../search/evidence_context.py) · [出处核验](../search/polity_evidence.py)

以濡须赏赐为例，“遣使者授以御蓋”支持物品，判断谁赏谁还要引同段接见、答话及身份依据。若本次清单只含最后一句，系统可以释读“遣使授予御盖”，对施受双方保留未知。交换两人后，即使引用编号完全有效，也不能显示反向赏赐结论。已有程序核实的字段可以明确标出，并保留依据；超出这些字段的模型解释标为草稿。两书出现差异时并列各自记载，先核对是否为同一人、同一事件；同书重叠切片和注文转引不能计作独立佐证。

## 实施顺序和验收

| 阶段 | 交付 | 进入下一步的条件 |
|---|---|---|
| 一、本地释读 | 先用保存的真实搜索结果接通快照、原文校验和单段生成，再接到桌面统一入口。保留纯检索对照 | 先检查固定正反题，再检查独立材料。用户能读到原文、逐句点击出处，证据不足时能正常结束 |
| 二、多文献问答 | 对同一事件并列展示不同版本、来源和时间，逐项生成有引用的比较 | 人工逐条核对事件是否相同、来源是否独立、异说是否真的存在，记录错误合并及错误确认 |
| 三、针对性改进检索 | 分析有效原文未入池、入池后落在前五外、前五有证据却判错的比例 | 前两类失败才调整召回或排序。沿用现有语义索引作对照，根据实际缺口决定是否增设组件 |

第一阶段的最低成本实验是固定同一份材料，比较“只显示原文”和“原文加 4B 释读”。先用一正一反检查能否回答及正确拒答，两题看到同一混淆段。通过后再跑预先冻结的六道独立题，覆盖显式事实、姓名省略、他人引述、同人异事、材料冲突及无充分依据。有充分原文却一律拒答也计为失败。新题的出处、可接受的其他版本及判据在生成前冻结。人工复核由开发验收承担。

每题分别记录前五是否有充分原文、可回答题的正确作答数、正确且有引文支持的主张数、错误确认数、拒答是否适当、桌面引用跳转是否准确。记录搜索、模型冷启动、首字、生成完成耗时以及超时次数。候选交付门槛为引用全部可定位、反例和证据不足题零错误确认、每道可回答题至少有一条直接作答且获原文支持的主张。小样本通过只开放桌面实验选项；默认启用需要独立扩大验收。若模型持续张冠李戴，保留检索和原文对照，记录具体错误，暂停扩大生成范围。
