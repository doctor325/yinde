# 简短判读说明与结构化输出的小诊断

2026-11-16，基于caf2f32。复用4B与已曝光正反开发题，不下载模型、不改gold、不更新桌面包。

## 推理前固定的对照与判据

基线为`src/data/evidence-reader/numbered-window/82443465c4d0/report.json`的v4结构化判读。
通过既有严格基线校验重建输入；保持问题、原文窗口、编号、身份线索、省略范围及问题解析
逐项一致。特别保留反题的魏王对象和待核实原因，不重新解析、不重新选择原文。
expected_answer及人工评分只存在本地报告，不发送给模型。

使用相同Qwen3-4B Q4_K_M、固定llama.cpp CPU运行时、4线程、8192上下文、非思考模式、
temperature=0、seed=20261111、650输出tokens、单请求120秒。只执行每题一次判读，
复用历史结构化输出，不重跑基线或留出题。

改变的是输出接口：系统说明改为简短自然语言判读要求，去掉字段填写指令及JSON schema
生成约束；输入数据载荷仍完全相同。要求交代人物、动作、对象、原因、动作状态及陈述来源，
引用编号，然后判断是否支持所问事件。系统说明保持通用，不含人名特例或已知答案。
**本实验同时改变提示措辞与输出语法约束，不能单独量化JSON语法的因果影响。**

主代理逐项复核仍保留原判据，只允许自然语言表达相同含义，不要求英文字段标签：

| 维度 | 正题要求 | 反题要求 |
|---|---|---|
| 人物、动作、对象 | 指向陈平实际离开项王事件 | 分清所问魏王与所给原文事件，不能把魏无知/汉王当作魏王 |
| 原因 | 惧诛，依据原文 | 不将离项王原因移用于离魏王，不补造离魏原因 |
| 状态 | 明确已离开，不能当拒绝接受任命 | 所引事件状态须与原文相符 |
| 来源 | 史家叙述，不能当指控或人物自述 | 陈述来源须说明且正确 |
| 引用 | 原文短语/编号实际支持所作说明 | 引用能支持事件区分及依据不足的解释 |
| 判断与解释 | 原因有据，无额外无依据推断 | 明确无法据此确认所问事件；仅说“否”不够 |

缺失维度记为未确认；只有全部满足才算完整通过。正确编号、停止正常、文字流畅本身不计为
语义正确。局部原文仍未包含较早离魏事件，不能宣称已核对整篇或知道其真正原因。

自动检查仅盘点引用编号、未知/不完整编号及其原文坐标，不抽取字段后冒充人工语义评分，
不产生eligible=true。原始文本（包括截断输出）完整保存；超时不重试、不计正确拒绝。

## 判读方向的预先约定

若简短说明正确且维度完整，而旧结构失败，说明此接口下4B能完成这两个开发问题，
下一步可研究输出组织；仍需要独立验收，不能宣布一般语义能力已解决。
若简短说明仍混淆事件，则说明问题不只在JSON字段填写，应停止继续堆字段，转向更强
判读方案的评估。若仅缺少维度或超时，则记录证据不足，不强行归入任一结论。

## 结果：速度改善，仍有超出证据的解释

运行目录：`src/data/evidence-reader/brief-diagnostic/bc402a36628f/`，原文输入、原始输出、
请求指纹、引用坐标和运行日志均保留，未覆盖基线。模型启动3.748秒，两个请求各完成一次。

| 项目 | 结构化基线：正题 / 反题 | 简短说明：正题 / 反题 |
|---|---|---|
| 判读耗时 | 56.991 / 49.996秒 | 23.710 / 17.873秒 |
| 输入tokens | 860 / 890 | 756 / 786 |
| 输出tokens | 345 / 289 | 192 / 138 |
| 缓存输入tokens | 3 / 3 | 0 / 264 |
| 完成输出 | 2题 | 2题 |
| 完整验收通过 | 0题 | 0题 |

正题正确指出陈平因惧诛而离开项王，e6支持这一主干，e10支持后续归汉。
但说明又把“因恐惧逃走”与“主动离开”对立，并断言“而非其他原因”；局部窗口不足以支持
这种主动性判断或排除所有其他原因。它还纠结于原文没有直接使用“离开”字样，给出
“并未直接记载离开的原因”的反复解释。状态的主干已表达为实际逃离，不能因为没有
英文字段就判错；失败在额外无依据推断、解释及来源维度未交代。

反题最终认为所提说法“缺乏直接证据支持”，比结构化基线的错误确认有所改善。
但其理由新增“项羽要诛杀事件发生在陈平离开魏王之后”。较早离魏原文已经在省略区，
当前给定窗口不能核验这个先后关系；不能将模型记忆或问题自身补进证据。
其“秘密行走在杖剑中逃离”也误处理了原文的动作短语。开头直接断言“并非因为”，
比当前材料只能说明依据不足更强，不能只凭末尾拒答就宣布正确。

| 原判据维度 | 正题复核 | 反题复核 |
|---|---|---|
| 人物与事件对象 | 主干对应陈平离项王 | 以窗口外时序作区别，所给依据不足 |
| 原因 / 支持判断 | 核心原因正确；排他性判断无据 | 拒绝确认方向改善；论证无据 |
| 动作状态 | 表达为实际逃走；主动性限定无据 | 实际逃离主干存在，但动作短语被误解 |
| 陈述来源 | 未说明属于史家叙述，未确认 | 未说明属于史家叙述，未确认 |
| 引用 | e6/e10支持主干，不能支持全部说明 | e5/e6不能支持补出的离魏时间顺序 |
| 最终解释 | 不完整且包含无依据推断 | 含无依据时序与动作误读 |

两题所用编号都存在且来源完整；引用盘点因此没有unknown/incomplete，
**这不等于引用支持全部断言。** 没有因输出自然语言而默认补齐缺失的来源类别。

## 诊断结论与方向

当前4B能够抓住这段材料的核心原因，简短接口也改善了反题的结论方向；不能笼统说它
完全不懂语义。但去掉复杂JSON后，仍然出现证据外时序、动作误读和无依据排他判断。
所以瓶颈不只是字段填写或JSON生成，原文理解、指代/事件对齐及证据边界仍不稳定。

按事先约定，**停止继续为这两题调整字段或提示，转向更强判读方案的评估**。
结合上一轮8B CPU反题超时，不再把“下载更大CPU模型”直接当成解决方案；后续候选应
同时满足运行期限和完整正反判据，再考虑独立真实材料与接入。当前不更新桌面或默认搜索。

这只是同一人物的两个曝光开发题；没有独立泛化结论，也不能量化JSON约束单独造成多少
错误。此次系统措辞、输出约束、输出长度及缓存状态共同变化，历史运行负载也未控制。
表中是实际测量值，不能宣传为稳定加速倍率。
