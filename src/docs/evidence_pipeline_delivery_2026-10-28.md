# 问题解析、多路召回、上下文核查桌面交付报告

## 1. 任务概述

按用户要求落实完整检索链路并更新本机桌面版。新增独立方式“问题解析＋上下文核查”（strategy=evidence）。默认仍为旧增强模式，因为本轮新方法并未在所有对照中更好。使用仓库内已有BGE-small向量与BGE-reranker-base模型，无下载、训练、云调用或生成回答。

## 2. 执行结果

1. 解析：复用通用关系词与主体线索，额外标出时间、地点、原因、数量回答槽位；解析失败保持unsupported，不编造结构。
2. 召回：向量、关键词扩展、主体关系候选三路交错选取，按片段ID去重。主体扫描最多4000，向量60，模型比较总预算24。预算与截断明确记录。
3. 上下文：取相邻片段，严格要求同页、同书、同修订、同source hash、同正文/注释层、同标题。原文保持独立引用；不能跨版本拼成一句。
4. 模型比较：以问题和“当前片段＋相邻上下文”成对输入本地cross-encoder，限制字符与token长度并记录截断。重排分是相关性分，不是蕴含概率或答案正确率。
5. 要素核查：检查当前事件句的主体/约束、显式关系句式与回答槽位。相邻段仅有日期不能自动填给当前事件；缺少要素明确显示“证据不足”。符合者仅标“包含所问要素与句式线索（未核实）”，不会宣布事实成立。全程relation_verified=false。
6. 界面：可展开实际参与核查的相邻原文并跳转精确位置；有本机trace记录。源码API、前端与正式EXE均已接入，不再只是离线模块。

这是一条完整的可运行、可观察和可验证流程，**不等于实现通用语义理解或自动判定答案正确**。解析和要素核查仍有限规则；上下文模型承担相关性比较，不能可靠解决指代、否定和因果。

## 6. 未解决问题

现代问题到古文的实体别名、简称和复杂关系解析仍会失败。模型比较预算有限，已召回候选可能未被选入24条；不能由重排补回未召回的证据。要素核查只能提示线索，无法可靠确认日期属于哪次事件、因果是否成立或多个人物角色关系。模型单纯高分不够，故仍保留“证据不足”与未核实标记。
