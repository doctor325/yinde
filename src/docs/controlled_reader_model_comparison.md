# 受控模型能力对照：冻结v4判读输入

2026-11-15，基于e0730bd。仅离线实验；不增加提示字段、不改原文或gold、不接入默认搜索。

## 推理前固定的方案

- 基线：上一轮Qwen3-4B Q4_K_M的原始输出，目录
  `src/data/evidence-reader/numbered-window/82443465c4d0/report.json`，完整语义验收0/2。
- 候选：[Qwen官方Qwen3-8B-GGUF](https://huggingface.co/Qwen/Qwen3-8B-GGUF) Q4_K_M。
  同系列同量化，选择目的是比较更大模型是否改善既有误读，不预设结果。
  固定revision `7c41481f57cb95916b40956ab2f0b139b296d974`，文件5027783488字节，
  SHA256 `d98cdcbd03e17ce47681435b5150e34c1417f50b5c0019dd560e4882c5745785`，
  依据官方模型API的LFS元数据锁定；下载到仓库已忽略的数据目录，模型不入git。
- 共用llama.cpp b12283 CPU x64、4线程、8192上下文、GPU layers=0、非思考模式、
  temperature=0、seed=20261111、JSON schema、650输出tokens、单请求120秒。
  启动期限仍为60秒；不因8B更慢而延长期限。
- 两题的370字/15单元、来源坐标、省略范围、v4判读提示与schema完全相同。
  冻结基线已正确解析的问题结果及待核实说法，8B仅判读；不再运行问题解析，
  不能把本实验当作8B解析能力评测。请求发送前核对字段、生成参数、消息和schema，记录hash。
- 复用4B历史输出，不重跑已完成的调用。准确性按相同输入比较；耗时并非同期、同负载
  多次测量，不能将差值全部归因于参数规模。两题都是已曝光开发题，没有独立泛化结论。
  4B当时未保存原始HTTP请求hash；本轮按其冻结代码、提示hash、逐项相同的编号证据与
  解析结果重建输入并核对字符数，再为8B实际发送的请求记录指纹，不把重建说成当时的网络抓包。
- 保留原验收：正题必须原因、事件对象、departed状态、narrator来源、引用与解释全部正确；
  反题必须识别事件错配/证据不足，insufficient且空答案，解释及对象引用不得混淆。
  只输出“否”、被guard拦截、JSON合法、短语出现，均不算语义通过。
- 每题只尝试一次。若发生请求超时或运行错误，不在仍可能取消中的服务器上排队下一题；
  记录未运行项，退出清理，不重试、不把未运行计为正确拒答。

## 实现边界

LocalReader仅增加显式模型选择，默认仍4B；8B采用独立receipt和官方hash，不自动回退。
下载入口可显式选8B，已有固定运行时直接复用；不修改用户配置、全局环境或桌面包。
比较入口检查基线冻结题/hash、模型身份、提示、原文及编号，再重建原判读请求。
不会把expected_answer或人工复核结果发给模型。

## 实测结果与逐项复核

运行目录：`src/data/evidence-reader/model-comparison/a805d3a3f335/`，包含report.json、
本次与前次运行日志。8B模型文件通过官方大小及SHA-256校验，启动耗时8.238秒
（不包含启动前的文件hash校验）。两题各尝试一次，没有延长期限或重新生成答案。

| 判读项 | 4B历史基线 | 8B本次对照 |
|---|---|---|
| 正题判读耗时 | 56.991秒 | 105.265秒 |
| 正题原因主干 | 正确 | 正确，答出惧诛及离开经过 |
| 正题来源类型 | narrator | narrator |
| 正题完整验收 | 未通过：状态、摘录和解释有错 | 未通过：引用缺失、摘录及状态未满足契约 |
| 正题解释 | 将籍贯误用为投奔依据 | 没有重复这一无依据推断 |
| 反题判读耗时 | 49.996秒 | 120.008秒触发请求超时 |
| 反题判断 | 错误确认离魏事件 | 没有完整输出，无法判定语义 |
| 完成输出数 | 2/2 | 1/2 |
| 完整验收通过数 | 0，2题均可复核 | 0，另1题超时无法复核 |

8B正题逐项问题：actor/action/object/state/attribution的引用数组为空；attribute填了
“原因”而非原文原因短语；action填“離開”而非要求的原文摘录；state仍用occurred，
未满足事先固定的departed约定；开放问题claim错误填supported。
其答案主干和rationale是正确的，不能因为这些契约错误就笼统说它不理解正题。
但也不能据此跳过原先的引用、状态与解释要求，宣布完整通过。

反题日志显示模型一直在生成，客户端到达120秒后退出清理；没有返回可供评分的完整JSON。
**反题应标为运行超时、语义未知，不能算正确拒绝或语义错误，更不能报告错误确认率下降。**
本轮只观察到一个完成输出，不报告可推广的模型准确率。

正题8B报告860输入tokens、145输出tokens，cached_tokens=0。
运行日志拆分为输入处理55.567秒、生成49.685秒，约2.90生成tokens/秒。
4B历史正题为860输入、345输出tokens，cached_tokens=3。
8B反题日志显示选择了前缀复用，但超时未返回usage，缓存token及完整输出token数保持未知。
4B原运行中穿插问题解析，8B本轮连续判读；缓存状态和机器负载并不等价。
因此耗时是当前配置下的实际观察，不是严格的同批速度倍率比较。

## 结论

**证据不足以认定8B在本项目的判读任务上更可靠。当前CPU/120秒配置下不接入8B。**
正题解释有局部改善，完整契约仍失败；最关键的错误事件反例没有完成，无法验证是否改善。
这不证明8B一般语义能力不如4B，也不证明4B已可用。两者仍只处于隔离实验。

下一轮应先分开诊断“事件理解”与“复杂结构输出”的负担，保持同一证据与完整的最终验收
要求，不能只靠输出格式失败推断理解能力；暂不继续扩大CPU模型或增加提示字段。
若要作模型选型，还需要完整反例结果和少量独立真实材料，目前不作选型结论。
