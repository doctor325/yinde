# 有出处的事件上下文与本地判读实验

本轮从 d070c91 开始，新增独立离线原型；默认检索、正式语料、排序、桌面包均不修改。
目的：把“补更多句式规则”改成可测量的上下文判读实验。实验失败也必须保留，不能接入默认入口。

## 实现

- `search/evidence_context.py` 从标点来源库恢复候选对应的原文块。校验页、书、修订、来源哈希与
  chunk parts 的逐字重建；在同标题、同正文层内按完整句／引述扩展，去除索引重叠带来的重复。
  默认最多3200个原文字符，明确记录范围截断、句段截断、引号不闭合。开篇身份另作来源线索，
  不把整卷动作归给传主。这里的“上下文”是有界来源上下文，不保证已覆盖完整历史事件。
- `search/evidence_reader.py` 统一人物、动作、对象、时间、地点、原因、状态、归属与引文字段。
  原问题始终保留，旧解析结果只是候选解释。规则观察保留原始数据和来源偏移；模型输出另存。
  JSON结构、引用真实性、模型语义判断三个层面分别记录；`semantic_verified` 永远不会因为
  JSON合法或引用存在而变为true。
- `search/local_evidence_reader.py` 只由实验命令显式启动本机CPU进程，监听127.0.0.1，
  使用随机访问令牌、禁代理的回环客户端、离线模型路径、超时与退出清理。
  原文和问题不发送到云端。未导入生产API、默认搜索或桌面启动器。
- `scripts/setup_evidence_reader.py` 下载固定版本公开资源到已忽略的 `src/data/evidence-reader`，
  校验官方文件大小与SHA-256，保留receipt。没有系统安装或用户配置修改。

运行时：llama.cpp b12283 Windows CPU x64；模型：Qwen/Qwen3-4B-GGUF Q4_K_M，
revision `bc640142c66e1fdd12af0bd68f40445458f3869b`，模型SHA-256
`7485fe6f11af29433bc51cab58009521f205840f5b4ae3a32fa7f92e8534fdf5`。
CPU 4线程，8192 context tokens，非思考模式，temperature=0，seed=20261111，
单次最多1100输出tokens、120秒请求期限。原文字符上限不等于token上限。

技术依据：[Qwen官方模型](https://huggingface.co/Qwen/Qwen3-4B-GGUF)、
[llama.cpp固定发布](https://github.com/ggml-org/llama.cpp/releases/tag/b12283)、
[结构化输出说明](https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md)。
模型卡和JSON约束都不能证明古文事件判断正确，必须看下面的实际输出。

## 冻结样本与边界

40题／20人，覆盖秦、汉、三国、晋、南北朝、唐、宋、明。
每人一条正例与一条角色、事件、时间地点、否定、转述范围或证据不足对照。
原文先读、问题先固定，再实现reader；frozen.json保存样本SHA-256，旧gold不改。
每题记录来源页／修订／hash／原文块偏移及预期解释，来源逐字校验。

本轮开发12题、留出28题，同人同篇章不跨组。旧JSON扫描发现其中7个人物在过去题库出现，
包括留出组6人，因此另存prior_overlap.json；不能把全部留出题称为新人物盲测。
未检出既有同名的留出为8人16题，此有限检查也不构成完全独立的盲评。

本轮是**给定来源候选的证据判断**，不测真实检索召回和Top5。
40题A/B使用同一冻结候选：A原片段和现有规则审计；B恢复上下文和同一规则审计。
这里调用的是规则审计核心，不是包含所有召回／本纪附加观察的完整生产管线。
C先导仅8题（陈平、邓禹开发；王维、宋濂留出，各一正一反），也使用同一候选。
不向真实搜索注入gold，不用本实验的候选存在宣称召回提升。

## 已完成验证

本轮只安排三条直接相关命令：6项契约单测、40题A/B、8题本地C先导。
6项单测通过，覆盖来源边界、版本／hash／位置错配、重复片段、长引述截断、伪造引用。
40题来源检查通过：A、B均未确认20条正例，也未误确认20条反例。
这不是规则准确率达到50%；拒绝全部证据不具有回答能力。
仅扩大上下文没有让这些正例通过当前解析与句式判断。
20条正例的A/B都报告主体或约束未同时出现、缺少全部关系明确主谓句式；其中5条还报告
无法可靠解析问题关系。因此本实验不能把所有失败单独归因于“证据审计”，问题解析也是瓶颈。
上下文恢复保留而未修补源文本的引号问题；邓禹样本的所选上下文被标记引号不配对。

模型原始输出、引用校验、人工语义复核与耗时见同目录的 `context_reader_pilot_result.md`。
原始报告保存在本机 `src/data/evidence-reader/ab-rules.json` 和 `abc-pilot.json`，不提交运行日志。

## 后续验收门槛

1. 先看模型输出是否真的回答同一人的同一事件，是否把指控／传闻升级为事实；不能仅看guard是否拦住。
2. 新候选模型／上下文预算如需比较，保留此次失败结果，开发与留出分别统计，不修改冻结答案。
3. 条件判读达到可用后，再从统一搜索入口保存真实候选池，固定所有策略的候选与模型排序，
   测召回、正确证据Top5、错误确认和端到端耗时。当前这些指标没有测量值。
4. 尚未满足准确性和交互耗时要求前，不更新桌面默认流程。不以结构化输出代替真实语义验收。

秦至明每位君主至少5条的全时期覆盖继续作为单独任务；40题不能替代该要求。
