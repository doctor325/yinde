这些是给定来源的条件判断，非召回率或Top5。A/B调用现有规则审计核心，
不是完整生产入口的所有身份／本纪附加观察。正确材料来自事先固定的来源。
守卫拒绝所有输出，不等于语义准确率100%，也不代表这一版已解决用户的问题。

8题C均成功完成推理、返回合法JSON，无超时；模型原始verdict有6条supported，
但没有一条完成逐字段引用与事件状态约定。6题的所附引用能够逐字定位，
其中仍有明确语义错误，证明引用真实性不能代替人物和事件判断。
各题都把来源归属标成speaker，不能据此把史家叙述当作当事人自述。

人工逐条对照冻结原文（非第二位独立标注者）得到：

| 题目组 | 原始模型表现 | 关键问题 |
|---|---|---|
| 陈平离开项羽 | 错答为项羽不信任他 | 原文依据是担心被诛；引文还被改成简体，无法逐字定位 |
| 陈平离开魏王的原因对照 | 输出conflicting、无答案 | 两个不同事件并非史料互相矛盾，引用也不忠实 |
| 邓禹追上光武的地点 | 答案短句“邺”正确 | 主体／动作／对象未提供字段引用，归属错误；上下文另有源引号问题 |
| 邓禹是否在长安追上光武 | 擅自改问时间，并补出“建武元年正月” | 引用虽真实，却不支持所填日期；没有忠实回答原问题 |
| 王维进士年份 | 答案短句“开元九年”正确 | 字段引用不完整，叙述误标speaker |
| 王缙进士年份对照 | 错套王维的开元九年 | 真实引文讲的是王维，模型未区分人物 |
| 宋濂拒赴元朝翰林编修 | 答案短句“亲老”正确 | 未明确拒任状态，缺人物／动作字段引用，来源归属错误 |
| 宋濂是否因双亲已去世拒任 | 输出conflicting、无答案 | 把“亲老”与错误前提理解成冲突，解释同时说原因未明与因亲老，逻辑不一致 |

4条正例有3条答案短句与原文相符，但均不满足完整证据约定，不能报“75%准确率”。
两条反例原始输出存在明显误读／补造；被当前守卫拦住不意味着更完整的错误输出也能被拦住。
没有声称所有正反例都得到可靠语义判断。

## 耗时与资源

本机CPU 4线程；模型一次加载约4.03秒（文件SHA检查耗时另计）。
8题请求总耗时637.20秒，单题39.05～115.69秒，中位数82.56秒。
输入上下文、缓存复用不同，这些数值是本轮观察，非稳定压力测试或独立冷启动分布。
8题后自有模型进程退出，数据库和HTTP响应均按作用域关闭。
该延迟不足以支持默认交互式搜索，更不能对每个候选都串行运行一次。

## 决策

保留已实现的来源上下文、事件结构、逐字引用守卫和冻结题集；
**不把当前4B模型接入默认搜索，不把结构合法的输出展示成“已确认”。**

下一轮最有价值的是缩小并简化判读任务：将完整句／引述编号，模型引用证据编号而非反复抄写，
分开判断“问的事件是什么”“原文是谁对谁做了什么”“是否支持所问属性”，
保留指控／转述类型；再用开发题比较更强本地判读模型和延迟。
这是待验证方案，不能承诺换模型就会正确。

新的模型／提示词先只使用开发组；本轮先导8题已经曝光，后续作为回归。
32题C尚未执行，不补写通过；其中未检出既有同名人物且未进行C推理的留出为6人12题，
可继续作为下一轮有限留出，但不声称第三方盲测。
通过来源条件判断后，再做真实入口的固定候选A/B/C与Top5验收。
