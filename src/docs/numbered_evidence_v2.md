# 编号证据与分步判断（隔离实验）

源码基线91d4877。本轮不修改默认检索、语料或桌面包。

`search/numbered_evidence.py`将来源上下文转换为完整句／引述单元，连续原文块内的引述一起切分。
每个编号保留逐字文本、来源块偏移与角色。开篇身份和事件上下文不跨界拼接，截断或引号不闭合
的单元明确标记。模型只能引用编号，程序还原原文；编号存在不意味着语义成立。

第一步单独解析原问题的人物、事件、对象和所问属性，不输入史料或gold。
第二步同时接收原问题、解析假设与编号原文，判断人物／事件是否对应并输出依据或不足。
解析结果仍是假设；不把模型自报matched当作历史事实核定。

本轮复用上一版4条已曝光开发题（陈平、邓禹，各正反两题）和完全相同的保存上下文，
不加入gold，不改问题或答案，不运行留出题。同一Qwen3-4B量化模型、4线程CPU、每次请求120秒期限。
第一步最多180输出tokens，第二步最多650；报告保存两步输出与使用量以及总耗时。
这一轮改变了判读协议和调用次数，不能将差异归因于模型权重变化。

验证入口（从src执行）：

```
python -B -X utf8 -m unittest tests.test_numbered_evidence
python -B -X utf8 -m tests.context_reader.run_numbered
```

小范围单测3项通过，覆盖跨块引用、角色边界、截断、无效编号和“真引用不等于真判断”。
初次测试的角色边界预期误把三个句单元写作两个，已修正该新建合成fixture并重跑；
冻结真实题集及其判据未修改。总测试命令3条（单测初次、单测修正后、模型对照）。
本地结果在`src/data/evidence-reader/numbered-v2.json`，不提交模型或运行日志。

## 实测结论：未通过

4条开发题均在第二步触发120秒请求超时，未得到完整判断输出；运行器返回失败，
自有模型进程通过上下文退出关闭。超时不能计作正确拒答，无法据此比较错误确认率或答案准确性。
同题旧版请求分别为97.58、115.69、91.02、108.21秒并完成；本版没有达到耗时下降目标。

日志显示第一步问题解析约3.5～4秒，而第二步仅输入预处理就已很慢。
编号输入为每个短句重复附带role、complete等JSON字段，增加token数量；
首题4096输入token时预处理已约88.6秒、进度约70%。这是本轮表示方式的性能缺陷，
不是模型语义能力改善或退步的证据。第一步输出未在第二步异常时单独落盘，
因此也不宣称问题解析准确率提高；后续须补部分结果记录。

本轮保留已测的隔离原型与失败证据，不接默认、不发桌面、不调用更大模型、不延时重跑。
下一步应把模型输入压缩为“编号→原文”，角色/完整性标记按组传递，来源偏移留本地；
先静态核对全部文字与编号映射等价，再安排单题开发验证。保持原文和gold不变。
