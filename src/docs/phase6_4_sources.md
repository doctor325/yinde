# 二十四史语料骨架与来源登记（第六点四阶段 §10 / §12）

本文件回答一个问题：**二十四史我们各有哪些、各有多少卷、还差哪几部。**

数字有两个真源，都不是本文件：

- `scripts/pipeline/corpus_catalog.json` —— 人工维护的**应该有什么**（含来源、卷数、底本）
- `data/metadata/volume_coverage.json` —— `scripts/pipeline/manifest.py` 跑出来的**实际有什么**（库内实测卷号）

本文件是这两者的可读视图，供人一眼看全。**改数字请改 catalog，本文件跟着重生成**；
直接改这里会造成「文档说 130、页面说 33」的两套说法 —— 那正是本阶段要消灭的东西。

- 二十四史通行本合计 **3213 卷**（这是本项目的 Complete 定义：$C_{\text{total}} = 3213$）
- 已入库 15 部：**1275 卷应有 / 1013 卷实收（79.5%）**
- 未入库 9 部：1938 卷，其中 3 部上游本身也不全

**状态词的含义**（六态，与 `manifest.merge_catalog()` 一致）：

| 状态 | 含义 |
|---|---|
| `complete` | 底本卷数与通行本相符，机器实测核对过 |
| `partial` | **底本卷数 < 通行本卷数** —— 上游数字化只到某一卷，不是我们漏了 |
| `planned` | 登记在册，尚未下载/入库 |
| `verified` | 已入库 + 篇名覆盖 OK + 有召回用例背书（书级状态，与卷级状态并存） |
| `warning` | 篇名覆盖 < 0.90，结构解析有问题，**我们能修** |
| `failed` | 有正文却 0 篇名，或 FTS 探针查不到自己 |

`complete` / `partial` 是**卷级**结论，`verified` / `warning` / `failed` 是**书级**结论。
一部书可以同时是「卷级 complete + 书级 warning」（如國語）；页面上两块分开显示。

## 二、底本（§11：Book 与 Edition 是两个实体）

版本登记表在 catalog 的 `editions` 段，一处登记、处处引用：

| id | 名称 | 家族 | 来源 | 备注 |
|---|---|---|---|---|
| `wyg` | 文淵閣四庫全書本 | wyg | Kanripo `KR2a` 系列 | 15 部正史用它（史記除外） |
| `sbck` | 四部叢刊本 | sbck | Kanripo `KR2e` 系列 | 先秦文獻（國語、戰國策） |
| `tls` | tls 本 | tls | Kanripo 早期轉錄 | 上游未標底本；以篇為單位，**無卷級證據** |

**同一部书可以有多个底本** —— manifest 里每本书的 `editions` 一律是**列表**，
不是单个字段。本阶段每部书只有一个底本，但结构上不假设如此：将来给三國志补一个
百衲本，只需在 catalog 里加一条，页面不需要改。

两个**不能混**的概念：

- `expected_volumes` —— **通行本**卷数（外证，稳定，作为分母）
- `declared_volumes` —— **这部底本/来源**实际有多少卷（分母相同、分子不同）

三國志 `30/65` 里，65 是通行本，30 是这部 WYG 底本的边界。覆盖率
`coverage_ratio = available / expected` 用的是**库内实测**的 available，
不是 declared —— 登记了却没收进来的卷，不能算已收
（二者在核对通过时相等，不等就是 `count-mismatch` 错误）。

## 三、剩余 9 部正史的来源审计（§12）

**调查方法**（三个独立证据交叉，任一单独都不够）：

1. 上游 Readme 的目次链接清单（有多少个卷链接）
2. GitHub trees API 列出的实际文件数（`KR2a00xx_*.txt`）
3. 对两个大缺口，直接读 `_000.txt` 的目録 —— 它列的是**全部**卷，用它区分
   「上游只数字化了一半」与「底本残缺」

结论：

| 书名 | Kanripo | 上游实有 | 通行本 | 缺口 | 性质 |
|---|---|---|---|---|---|
| 舊唐書 | KR2a0026 | 187 | 200 | 缺 13 卷 | 上游数字化未完成 |
| 新唐書 | KR2a0027 | 75 | 225 | 缺 150 卷（全在列傳） | 上游数字化未完成 |
| 舊五代史 | KR2a0029 | 150 | 150 | 无 | 完整，可导入 |
| 新五代史 | KR2a0030 | 74 | 74 | 无 | 完整，可导入 |
| 宋史 | KR2a0032 | 496 | 496 | 无 | 完整，可导入 |

### 3.1 「缺的那一半在不在别的仓库里」——已排除

`KR2a0026` 附近的几个 ID 一度让人怀疑「新唐書的列傳是不是被拆到了邻号」。
逐个查过，它们都是**别的书**（校勘/辑佚类），不是本纪的续篇：

| ID | 是什么 | 判定 |
|---|---|---|
| KR2a0028 | 舊唐書 的校勘記（糾謬類） | 非正史本体 |
| KR2a0031 | 新五代史 的纂誤 | 非正史本体 |
| KR2a0034 | 遼史 的拾遺 | 非正史本体 |
| KR2a0037 | 遼史 國語解 单行 | 非正史本体 |

结论：**缺口就是缺口，不在邻号里。** 这四条记在这里，是为了下次有人找
「新唐書缺的 150 卷」时不必重查一遍 —— 它们不是那 150 卷。

> **它们没有进 `corpus_catalog.json`，这是有意的。** 目录里的每一条都会
> 参与三件事：在册书数（28 = 24 正史 + 4 先秦）、发布闸门的禁书名清单
> （`check_publish.REAL_TITLES` 从目录派生）、以及 `#/coverage` 的收录进度。
> 把四部**本就不在二十四史范围内**的校勘记塞进去，会让「24 部正史」这个数字
> 失真，也会让发布闸门多拦四个跟本项目无关的书名。**审计结论写在本文件，
> 登记表只放我们真要拥有的书** —— 这是两个不同的表。

### 3.2 不要为了完成数字而盲目导入（§12）

上游完整的 6 部（舊五代史、新五代史、宋史、金史、元史、明史）**本阶段不导入**。
理由：

- 本阶段的任务是**让系统知道自己有什么**，不是扩语料。导入会重建 DB、移动 6.3
  基线的全部数字（760k 记录），而本阶段没有任何一项验收要求语料变多。
- 旧唐书/新唐书/辽史三部上游本身残缺，导入之后**立刻**又是一批 partial ——
  先让「partial 该怎么说」这件事在 5 部书上跑稳，比一次多 3 部 partial 更划算。
- 导入是下一阶段的事。本阶段把它们**登记清楚**（含上游残缺的事实）就已达标：
  搜索页现在会正确地说「《新唐書》尚未收录」，而不是「正文中没有」。

### 3.3 逐部说明

**舊唐書（187/200，缺 13 卷）**
上游 `_000.txt` 目録列出全部 200 卷，实际文件止于卷一百八十七。缺的主要是
部分列傳末尾几卷。属上游数字化未完成。

**新唐書（225 卷实有 75）**
缺口 150 卷**全部在列傳**：本纪 10 卷、志 50 卷、表 15 卷是齐的，列傳只到卷七十五上。
已核对 WYG 分支与 master 一致，不是分支选错。这是本批里缺口最大的一部 ——
也正是它最能说明本阶段的价值：用户在「新唐書」里搜一个唐代人物，必然搜不到，
若页面说「正文中没有」，那是彻底的误判。

**遼史（115/116，缺卷 116）**
只缺国语解一卷（卷一百十六）。该卷以单行本形式存在于邻号 `KR2a0037`，
上游把它拆出去了。已登记，不计入正史本体。

**其余 6 部**：上游文件数与通行本卷数一一相符，可随时导入。
