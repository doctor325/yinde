# 原文先行、问题后核对实验（2026-11-17）

本轮实现独立实验协议`source-first-events-v1`。模型先只接收编号原文，整理事件；程序随后用同一份事件记录核对不同问题的人物、动作、对象。没有在旧两题提示后追加补丁，没有接入默认搜索或桌面版。

## 两阶段边界

第一阶段`source_first_reader.extract(reader, evidence)`只接受编号原文。请求构造器白名单仅保留`evidence/opening_context/incomplete`，不接收问题、解析结果、待验证说法、gold、题号或先前对话。模型输出事件的人物、动作、对象、原因、状态、陈述来源及证据编号，不输出“是否支持问题”。这些是模型读出的待核验记录，不是真值数据库。

同一窗口只整理一次，再供不同问题复用。问题不能回写、补齐或覆盖事件记录；原文位置和内容的哈希与记录绑定，文本或位置漂移拒绝复用。引用编号沿用原编号，不为提问重新切句或挑选支持答案的句子。本次入口另用原有冻结来源审计核验书目及修订；通用函数的编号证据哈希本身不含书目身份，不能单凭它跨书或跨版本合并同文记录。

窗口本身来自之前检索选取的冻结上下文，因此“这次模型看不到问题”不等于“窗口选择完全与问题无关”。原文、gold和既有问题解析均未改，仍不能据此证明端到端检索改善。

第二阶段`compare(question, extraction, evidence)`不再调用模型，逐个核对事件角色。保留原问题中的待验证原因；程序不会因为问题说了某个对象，就把原文事件对象换成它。

- 简繁字形及两端空格可归一；同名、同庙号不因此成为同一身份。别称、动作同义表达或省略角色尚不能证明等价时，记录`unresolved_difference/unknown`。
- 不跨事件借用另一事件的原因、状态或来源。相同人物的多次行为保留多个候选，不按最近距离或出现顺序任挑一个。
- 缺引用、不完整证据、仅有开篇身份、状态不明、拟议/拒绝/否定，以及引述/指控等来源，均保留未确认。这不是声称这些史料没有价值，而是当前实验未实现相应问句状态与来源的完整核对。
- 三个角色文字相同也只是`needs_semantic_review`。答案留空、`semantic_verified=False`；不能把原因缺失、错误原因、同名人物或同人不同事件自动标成已确认。
- 原文整理失败、截断、格式不合法或跨源复用时，程序返回未确认，不重试、不修补JSON、不让半截事件表进入核对。

这些约束阻止已知类型的错误升级为确认，但不等于通用人物消歧、动作语义或因果判读已经完成。当前版本会保守漏掉未对齐的称谓和动作表达，需要在真实模型结果中单独评估。

## 固定协议与成本

沿用已下载的官方Qwen2.5-14B-Instruct Q4_K_M、原CPU运行文件/参数和证据窗口。没有下载新模型或调GPU。模型请求最多650输出tokens、每次120秒，temperature=0、seed=20261111；同一窗口最多整理12个事件，覆盖不全必须保留partial/unknown，模型自称complete也不是完整性证明。整窗结构化整理可能比旧简短回答更慢，本轮必须记录此成本，不能延长预算掩盖失败。

这是新的协议：系统提示和输出格式发生了必要变化，调用次数从“每题调用模型”改为“一次原文整理＋程序核对”。因此不能把结果当作只改变模型大小的对照，也不能沿用旧模式的通过率标签。

## 下一步边界

优先处理**独立事件整理的执行粒度**，而非继续增加提示字段或更大模型。可研究按原文自然边界逐单元整理、增量保存并复用，保留跨句主体、完整引述和原因上下文；切分必须独立于问题及已知答案，失败单元保留未完成，不得用部分覆盖假装全窗已整理。应先估算模型调用数及总耗时，不能用大量小调用掩盖总成本增加。

本轮没有实现或试跑分批方案，也没有证明它能够改善速度或语义。后续需要单独冻结方案与预算，先验证一个通用完整事件单元，再决定是否扩展；不自动开启留出评测或桌面部署。

## 使用与交付

实验入口默认为离线准备；只有显式`--run`才启动仓库内本地模型。原始请求、原文、模型输出和运行日志留在忽略的数据目录，不提交Git。程序始终区分运行完成、角色核对和完整语义验收，不将任一未确认结果升级为“可能回答”。

仍需按原标准人工检查人物、动作、对象、状态、原因、陈述来源、引用支撑与补造；正题无答案与反题未确认不能一起统计成“两题通过”。没有更改旧gold或基线。
